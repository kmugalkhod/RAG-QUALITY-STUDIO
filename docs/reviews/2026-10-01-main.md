# Review, main (uncommitted), 2026-10-01

**Reviewed by**: Claude Fable 5.1 (author on a different model session)
**Scope**: 158 files, uncommitted working tree against HEAD `5b23cff`
**Verdict**: Changes requested

## Summary

This change closes out spec 0002: every Studio screen and the website widget move onto one token based design system with light and dark themes, a phone tab bar, a connection banner, new shared primitives and state components, a lint guard that rejects off grid styling, and a Playwright visual journey. It also carries one unrelated backend fix (a 5 second JWT clock skew leeway). The restyle is careful: I found no behavior regression in the API calls, validation, polling or focus handling across the feature screens, the guard works for what the spec says it checks, the widget palette ratios all clear 4.5:1 (lowest 5.18:1), and the `cn` merge config does real work. The headline problems are test gaps around new branching logic (the theme module has no automated test at all), a guard blind spot for class strings held in constants, duplicated and unbounded request fan out on Overview, and a few small behavior changes that slipped into a change described as UI only.

## Major

### 🟠 Theme selection logic has no automated test, `frontend/src/app/useTheme.ts:35-60` and `frontend/public/theme-init.js:3-23`
**Problem**: The theme module branches three ways (stored value, OS preference while nothing is stored, blocked storage) and wires a `storage` listener for other tabs, a `matchMedia` change listener gated on `readStoredTheme() === null`, and a `MutationObserver`. `grep -rln "useTheme\|ThemeToggle\|rqs.theme" frontend/tests frontend/e2e` returns only `e2e/visual.spec.ts`, which writes `rqs.theme` through an init script and asserts `data-theme`. Nothing exercises the toggle, the cross tab sync, the OS listener gating or the blocked storage fallback. The spec lists "Theme" as a critical test scenario and verify.md marks those steps as manual.
**Why it matters**: A future edit that drops the `readStoredTheme() === null` guard, or that stores a value other than `light` or `dark`, would pass lint, typecheck, 199 unit tests and the visual journey. The same gap covers the `document.hidden` gating of readiness polling in `DisconnectedBanner.tsx:52-58`, which no test toggles.
**Suggested fix**: Add a Vitest for `useTheme` that stubs `matchMedia` and `localStorage`: render, toggle, assert the attribute and the stored word; dispatch a `storage` event for `rqs.theme` and assert the attribute follows; fire the media change with and without a stored value. Add one DisconnectedBanner case that sets `document.hidden` and asserts no poll fires. Keep theme-init.js covered by the visual journey.

## Minor

### 🟡 The guard does not see class strings held in constants, object properties or ternaries, `frontend/scripts/check-structure.mjs:185-201`
**Problem**: `classStrings` collects literals only from `className="..."`, `className={...}` and `cn(` or `cva(` calls. I ran a copy of the script in the scratchpad against a probe file: a direct `className="p-5 text-2xl font-bold bg-purple-500 text-[13px]"` produced five violations, while `const PANEL = 'p-5 text-2xl font-bold bg-purple-500 shadow-md rounded-lg text-[13px]'`, an object property `row: 'gap-5 mt-7 h-[37px]'` and `const dynamic = on ? 'px-5' : 'px-7'` produced zero, even though `PANEL` is later used as `className={PANEL}`. The codebase already relies on this pattern (`frontend/src/app/BottomTabBar.tsx:36`, `frontend/src/main.tsx:111`, `frontend/src/app/WorkspaceSidebar.tsx:16`, `frontend/src/features/ingestion-pipelines/components/settingsStyles.ts`, `frontend/src/features/workspace/components/settingsLayout.ts`). A sweep of the real tree with every string literal scanned found no current drift.
**Why it matters**: The spec's user story is a lint rule that stops drift. Because the Tailwind scales are reset, most unapproved keys would at least produce no CSS, so the live risk narrows to bracket values such as `h-[37px]`, `font-bold` and color literals in constants, which do render. Review is the only net for those today.
**Suggested fix**: Scan every string literal in `.ts` and `.tsx` files with the same `classViolation` rules. The rules only fire on recognised utility shapes, so false positives are rare, and you can keep the raw element and style prop checks as they are.

### 🟡 Overview fetches the same lists twice and walks every page of indexes and experiments, `frontend/src/features/workspace/stages.ts:24-28` and `:51-55`
**Problem**: `loadPrepareStage` and `loadCompareStage` call `allPages(...)` over `listIndexes` and `listExperiments` to count `succeeded` rows, while `ProjectSummary` already loads documents, indexes and pipelines for the same route. `allPages` (`frontend/src/lib/pagination.ts:8-21`) is sequential and unbounded, and neither API accepts a status filter (`frontend/src/features/experiments/api.ts:21`, `frontend/src/features/documents/indexApi.ts:24`).
**Why it matters**: A project with a few hundred experiments issues a chain of requests on the most visited route, just to render "M completed runs", on top of the lists the page already holds.
**Suggested fix**: Derive Prepare and Ask from the data `ProjectSummary` already holds, and cap the experiment scan (for example two pages) showing "N+ completed runs" past the cap. If a `status` filter is added to the list endpoints later, read `total` instead.

### 🟡 Stage precedence differs from the spec's Value sourcing rows, `frontend/src/features/workspace/stages.ts:34-40` and `:58-64`
**Problem**: The spec says "0 documents is empty ('No documents')" and "no dataset is empty". The code checks `ready` and `completed` first, so a project with 0 uploads and one published index reads "0 documents · 1 ready index · Ready", and the same precedence applies to Compare. The code comment gives a sound reason (ingestion pipelines publish without uploads).
**Why it matters**: The spec is the contract reviewers check against; today it says one thing and the code does another.
**Suggested fix**: Keep the behavior and amend the Prepare and Compare rows in `docs/specs/0002-workspace-ui-redesign/index.md` so the precedence is written down.

### 🟡 StageStrip branch coverage, `frontend/tests/features/workspace/StageStrip.test.tsx`
**Problem**: The "Needs indexing" and "No completed runs" in progress states, `allPages` crossing a page boundary, and `primaryStage` with a failed Compare while the others are ready (returns `null`, so no primary anywhere) are not asserted.
**Why it matters**: These are the branches AC-6 describes, and the primary button rule is the one users see first.
**Suggested fix**: Two StageStrip cases for the in progress states and one `primaryStage` case for a failed Compare.

### 🟡 Settings section scroll is untested, `frontend/src/features/workspace/ProjectSummary.tsx:56`
**Problem**: `document.getElementById(`settings-${section}`)?.scrollIntoView(...)` is the only thing that makes the More sheet's Connections item land on Source connections, and no test renders `ProjectSummary` with `configuration` and `section`.
**Why it matters**: A renamed id breaks the phone path to Connections silently.
**Suggested fix**: A Vitest that stubs `scrollIntoView` and asserts one call after settings load.

### 🟡 Playground catalog failure and Retry remount are untested, `frontend/src/features/playground/components/PlaygroundView.tsx:103` and `:140`
**Problem**: `catalogFailed = !props.loading && !!props.loadError && !props.options` swaps the whole screen for an `ErrorState`, and Retry remounts through a key. `tests/features/playground/` holds only `AnswerResult.test.tsx` and `useQueryRun.test.ts`; the visual journey only screenshots the forced error.
**Why it matters**: This is the recovery path when `/indexes` fails, and it is new branching logic.
**Suggested fix**: One component test that fails the catalog, asserts the ErrorState, resolves the next load and clicks Retry.

### 🟡 New error states on Experiments, Comparison and Deployments have no unit test, `frontend/src/features/experiments/ExperimentsPage.tsx:31` and `:171`, `frontend/src/features/experiments/components/Comparison.tsx:82`, `frontend/src/features/deployments/DeploymentsPage.tsx:7`
**Problem**: The `loadError` state and its `ErrorState` with Retry, and the Deployments choice between `ErrorState` and the inline permission error, are only covered by screenshots. `ExperimentsPage.test.tsx` changed only the `toBeDisabled` assertions and there is no `tests/features/deployments/`.
**Why it matters**: AC-10 makes these states part of the contract.
**Suggested fix**: One test per route that rejects the list request and asserts the state component and Retry.

### 🟡 `summarizeNodeConfig` has no test, `frontend/src/features/pipelines/components/summarizeNodeConfig.ts:5-19`
**Problem**: Five branches, including the retriever line that composes `formatRetrievalSummary(...)` with "Documents selected" or "Choose documents" and the LLM fallback "Choose a model". `grep -rln "summarizeNodeConfig\|Choose a model\|Response + citations" frontend/tests frontend/e2e` finds nothing.
**Why it matters**: The summary line is the only configuration readout on a node card and AC-9 names one format per kind.
**Suggested fix**: A small table test over the five kinds, with the retriever case with and without `index_id`.

### 🟡 Node summary tooltips cannot be opened from the keyboard, `frontend/src/features/pipelines/components/WorkflowNode.tsx:55-57` and `frontend/src/features/ingestion-pipelines/components/IngestionPipelineCanvas.tsx:103-104`
**Problem**: `TooltipTrigger asChild` wraps a `<p>`, which never receives focus, so Radix opens the tooltip on hover only. The full text stays in the DOM for screen readers and the settings panel remains the accessible path.
**Why it matters**: AC-9 says the truncated line is "shown in full in a Tooltip"; keyboard users do not get that.
**Suggested fix**: Give the trigger `tabIndex={0}`, or document that node settings are the accessible path and the tooltip is a pointer nicety.

### 🟡 Retrieved passage text is now clipped with no affordance, `frontend/src/features/playground/components/RetrievalTest.tsx:63`
**Problem**: `line-clamp-4` on the passage paragraph; HEAD rendered `<p>{item.text}</p>` in full. The text is still reachable through "View passage N".
**Why it matters**: AGENTS.md asks that retrieved text stay inspectable, and this is a behavior change in a change described as UI only. The clamp is silent, so a reader does not know the passage continues.
**Suggested fix**: Drop the clamp, or add a visible "Show full passage" disclosure.

### 🟡 The project creation date disappears on phones, `frontend/src/features/projects/components/ProjectList.tsx:107-108`
**Problem**: The Created column is `hidden ... md:flex`, so the list shows no date below 768px; it was always visible before.
**Why it matters**: Information removed on one breakpoint in a UI only change, with nothing in the spec checklist saying so.
**Suggested fix**: Fold the date into the description line on phones, or record the omission in the spec checklist.

### 🟡 The Playground mode explanations are gone, `frontend/src/features/playground/components/PlaygroundToolbar.tsx:40-60`
**Problem**: The mode buttons lost "Find passages only" and "Find passages + generate an answer"; the only explanation left is the welcome text in the conversation area, which disappears once a result exists.
**Why it matters**: Users switching modes after the first question have no on screen hint of what each mode does.
**Suggested fix**: Keep a one line hint next to the mode group or a tooltip on each mode button.

### 🟡 The unrelated auth change rides in a UI feature, `backend/app/core/auth.py:29-31`, `:123` and `:144`
**Problem**: A 5 second `leeway` for `iat`, `nbf` and `exp` on both the OIDC and Clerk decoders. The value is conservative, the expiry rejection test was adjusted correctly (`backend/tests/test_security_controls.py:131`) and a new test proves tolerance at 2 seconds and rejection at 60. It does not weaken signature, issuer, audience, origin or session checks. But spec 0002 states "no backend file is edited in this feature".
**Why it matters**: A reader of the squashed commit will not expect an auth change inside a redesign, and the spec invariant is literally false.
**Suggested fix**: Commit the auth change separately with its own message. Consider noting in the constant's comment that the leeway also admits a token up to 5 seconds past `exp`, which is intended.

### 🟡 DisconnectedBanner polling test stops short and can leak fake timers, `frontend/tests/app/DisconnectedBanner.test.tsx:32-45`
**Problem**: The test is named "keeps failing to unreachable" but only asserts the first poll at 5 seconds; it never advances to prove a second poll after the 500. `vi.useFakeTimers()` is restored at the end of the test body, so a failing assertion leaves fake timers on for later tests.
**Why it matters**: The repeat schedule is the AC-7 behavior ("5 seconds after each response ends"), and a timer leak makes other failures confusing.
**Suggested fix**: Advance another 5 seconds and assert two calls; move `vi.useRealTimers()` into `afterEach`.

## Strengths

- `backend/tests/test_security_controls.py:145-178` is a good test for the leeway: it proves acceptance at 2 seconds of skew and rejection at 60, and the existing expiry test moved its boundary rather than being deleted.
- `frontend/src/components/ui/button.tsx` implements the AC-3 contract faithfully: `aria-disabled` with focus kept, click and implicit submit blocked in one handler, `href` stripped for disabled `asChild` anchors, loading that keeps width and the accessible name, and vibration gated at `pointerdown` in a try block.
- `frontend/src/lib/api.ts:123-133` feeds the connection store from one place, leaves user cancels and 4xx or 500 responses alone, and `connection.test.ts` covers each path including the 12 second timeout.
- `frontend/tests/app/tokens.test.ts` computes real WCAG ratios with alpha compositing and `color-mix` in oklab, so the colour table is checked rather than trusted. The widget palette holds up too: every fill against white and every accent on its surface is at least 5.18:1 in both themes (computed during review).
- `frontend/src/lib/utils.ts` teaches the class merger the named sizes; without it `cn('h-control-md', 'h-control-lg')` keeps both classes, with it the call site wins (verified).
- Every browser journey moved from class selectors to test ids, the Overview strip isolates each stage's failure with its own Retry, and the raw checkbox, select and textarea elements in the ingestion settings became primitives without changing the data each handler writes.
